1．イベント概要
Community Over Codeについて

Community Over Codeは、オープンソースソフトウェアの開発を支援する非営利団体、Apache Software Foundation（ASF）が開催する国際カンファレンスです。

オープンソースソフトウェア（OSS）は、ソースコードが公開され、ライセンスの条件に従って利用・改変・再配布できるソフトウェアです。旧称はApacheConで、2023年に現在の名称へ変わりました。技術について学ぶことと、コミュニティを育てることを目的にしています。

Apacheという名前からWebサーバーのApache HTTP Serverを思い浮かべる方も多いと思いますが、対象はそれだけではありません。データ処理、検索、クラウド、IoT（センサーや機器をネットワークにつなぐ技術）、組込みシステムなど、さまざまな分野のプロジェクトが集まります。

複数の会場で、分野やプロジェクトごとの講演が同時に進みます。この講演のまとまりを「トラック」と呼びます。

ほかにも、参加者が集まって開発するハッカソンや、共通のテーマについて話し合うBoF（Birds of a Feather）などがあります。技術を利用する人と、開発・運営する人が同じ場所で話せることも、このイベントの特徴です。

Apache Software Foundationの成り立ち

ASFの原点は、1995年にWebサーバーの改良に取り組んだApache Groupの活動です。そこから1999年に財団が設立され、現在は幅広いOSSプロジェクトを支えています。

特徴の一つは、財団の会員が企業ではなく個人であることです。各プロジェクトでも、継続的な貢献に基づいてソースコードの変更をリポジトリに反映する権限を持つ「コミッター」や、プロジェクトの運営・リリース承認を担う委員会「PMC（Project Management Committee）」のメンバーなどの役割を担っていきます。

もちろん、企業に所属する開発者も多く参加しています。企業によるスポンサー支援もありますが、企業としての支援と、プロジェクトにおける個人の役割は分けられています。

参考：ASFの歴史／ASFの仕組み

私は以前、日本で開催されたOpen Source Summit Japan 2025やKubeCon + CloudNativeCon Japan 2026に、ボランティアとして参加しました。Linux Foundationは、LinuxをはじめとするOSSの開発や普及を支援する非営利団体です。これらは、その財団や傘下のコミュニティに関わるイベントです。

同じOSSのイベントでも、運営母体の成り立ちには違いがあります。

観点	Apache Software Foundation	Linux Foundation

組織の特徴	個人による会員制度と、プロジェクトごとのコミュニティ運営	企業会員を含む仕組みを持ち、多様なプロジェクトや産業分野の協業を支援
イベントの紹介軸	Apacheの各プロジェクトと、その開発・運営に関わる人たち	幅広いOSS技術や、その周囲の開発者・企業・コミュニティ

単純に「企業のイベントか、個人のイベントか」と分けられるものではありません。Open Source Summitにもコミュニティ活動の講演があり、Community Over Codeにも企業所属の登壇者や企業の事例紹介があります。違いを見るなら、登壇者の所属よりも、何を中心に人が集まり、どのようにプロジェクトを支えているか、という観点が分かりやすいと思います。

資金面では、ASFには寄付やスポンサー支援があり、Community Over Codeにも参加費やイベント協賛の仕組みがあります。個人の活動を尊重するコミュニティが、企業からの支援も受けながら続いている構造です。

制度概要・応募条件

TACはTravel Assistance Committeeの略で、経済的な理由で参加が難しい人に対して、ASFのイベントへの参加を支援する仕組みです。

公式の案内では、交通費、会期中の宿泊費、カンファレンス参加費が支援対象とされています。一般的な生活費は対象外です。また、原則として支援金を本人へ振り込む形ではなく、ASFや指定業者が交通・宿泊を手配して支払います。

応募はオンラインで行い、申請内容に基づいて審査されます。参加が本人にとってだけでなく、ASFやOSS全体にどのような意味を持つかも重視されます。居住地に近い開催地への申請が一般に優先されますが、遠方のイベントへ参加する理由も考慮されると説明されています。

支援枠と予算は限られているため、応募すれば必ず採択されるわけではありません。

7．聴講・ハッカソン・交流（SpresenseでのDOOMなど）
講演メモ

自分の発表以外にも、組込みからデータ処理、検索、AI、OSS教育まで、幅広い話に触れました。ここでは、当日のメモに残っている講演を短く紹介します。

Apache AirflowとAIエージェント

Airflowは、複数の処理を決められた順序や時刻に実行し、結果を管理するソフトウェアです。講演では、その処理の中にAIエージェント（目的に沿って処理やツールを選び、作業を進めるAI）を組み込み、実行状況を把握したり、人が確認・判断したりする仕組みを扱っていました。

Apache StreamPipesと産業IoT

センサーや機械からデータを取り込み、加工・保存・可視化へつなげる産業IoT基盤の紹介です。画面上の操作で処理を組み立てる仕組みや、機器との通信方法、クラウドサービスとの違いなどに関心を持ちました。普段扱っているエッジ機器や、工場の設備を制御するPLCにも近い話題でした。

Open Source Software Engineering Education in an AI Encumbered World

AIが使える時代に、ソフトウェア工学やOSSへの参加をどう教えるか、という講演です。登壇者はCarnegie Mellon UniversityのStephen Walliさんでした。実際のプロジェクトに参加して、レビューや協働、運営を学ぶ教育に関心を持ちました。OSS、大規模言語モデル（LLM）、ソフトウェア開発の教育、人とコンピューターの関わりが交わるテーマとして、今後も考えてみたい内容でした。

特に印象に残った論点は三つあります。

一つ目は、ソフトウェア開発には、チームや利用者の間の「暗黙知」があるという点です。講演では、Peter Naurの論文「Programming as Theory Building」（1985年）に影響を受けた考え方が紹介されました。スライドには、暗黙知のギャップがなければバイブコーディング（AIに指示してコードを書かせる開発スタイル）はうまくいく、という趣旨の表現がありました。逆に言えば、設計の意図やプロジェクト固有の事情といった暗黙知は、AIがコードを出力できるだけでは埋まりません。

二つ目は「All Software is Social Software」という考え方です。OSSはコードだけでなく、Issue、Pull Request、レビュー、メールでの議論、リリース、コミュニティへの参加といった社会的な実践で成り立っています。

三つ目は、ガバナンス（プロジェクトの意思決定の仕組み）は、文書に書くだけでなく実践だということです。実際の意思決定やレビュー、メンタリングの積み重ねを通じて形づくられ、伝わっていくという話でした。

教育の実践例としては、大学の授業でOSSプロジェクトに参加する取り組みが紹介されました。2024年のCMU Qatarでは、約10週間（講義6週間、リモートでのOSS実践4週間）で、成功した例として挙げられていました。一方、2025年にQatarとPittsburghの混成チームで行った試みは、期待する作業時間と実際の投入時間が合わず、うまくいかなかったという率直な報告でした。

自分自身、Claudeを使って、初めてのOS開発に取り組みました。コードは速く書けても、その中身を理解して検証するのは人間の仕事で、そこが一番大変でした。この講演の「暗黙知」の話は、その実感と重なりました。

6 years of fuzzing Arrow and Parquet C++

Arrowは大量のデータをメモリ上で効率よく扱う仕組み、Parquetは分析用データの保存形式です。これらをC++で実装したコードに、多様な入力を与えて不具合を探す「ファジング」を6年間続けてきた取り組みでした。検証の技術に加え、活動の継続や、それを支える資金についても考える機会になりました。

NuttX-based Altimeter for High Powered Rocketry

NuttXを使ったロケット用高度計の講演です。飛行データの記録や、パラシュート展開などの機能を、具体的な機器として実装する話でした。機械・航空やロボティクスを学んできた自分にとっても、特に関心のあるテーマでした。

OpenGL ES on Apache NuttX: the µGLy project

OpenGL ESは、組込み機器などで図形や3Dの映像を描くための共通の規格です。µGLyは、その規格の一つであるOpenGL ES 1.0 Common LiteをNuttXで使えるようにするプロジェクトです。メモリなどの制約が厳しい環境で、共通の規格を使えるようにする狙いに関心を持ちました。

Bringing NuttX to Raspberry Pi 4B

小型コンピューターのRaspberry Pi 4Bへ、NuttXを移植する取り組みです。Linuxでおなじみのボードを別のOSで動かす話として、移植時にどの部分から機能を揃えていくのか、NuttXの対象を広げる意味は何か、という点に関心を持ちました。

Everything, Everywhere, All Embedded: Apache Tika 4.x in Your Search Stack

Tikaは、さまざまな形式のファイルから、本文や作成者などの情報を取り出すソフトウェアです。講演では、PDFの本文だけでなく、図や表、画像の情報も検索に使う取り組みを紹介していました。画像と言葉を一緒に扱うAIモデル「VLM」の活用や、抽出結果の誤り、ファイル内に残る思わぬ情報の扱いも話題になりました。

Apache Luceneのベクトル検索

Luceneは、アプリケーションに検索機能を組み込むためのソフトウェアです。文章などの特徴を数値の並びに変換し、似たものを探す「ベクトル検索」の高速化がテーマでした。検索に使うデータ構造や数値の保存方法を工夫して、処理速度やメモリ使用量を改善する取り組みです。

同じApacheのイベントの中に、これだけ異なる分野が並んでいることも印象に残りました。それぞれのソフトウェアの背後に、開発を続ける人とコミュニティがいることが、少し具体的に見えるようになりました。

NuttXハッカソン

10月14日には、NuttXのハッカソンにも参加しました。公式の事前案内では、ソニーの小型開発ボード「Spresense」などを使って、NuttXのソースコードから実行用のプログラムを作り、動かす企画として紹介されていました。

会期最終日の午前から昼過ぎにかけて行われ、私はTACの運営業務と両立させながら参加しました。

今回の成果の一つが、Spresense上での、3Dシューティングゲーム「DOOM」の動作です。ゲームのデータ（WADファイル）を用意し、画面を表示するLCDコントローラの種類を確認しながら動かす、といった作業がありました。開催後の公式レポートでも、会場でこの目標を達成したことが紹介されています。

私もハッカソンでの成果を共有しました。講演を聞くだけでなく、実機を囲んで取り組み、その結果を人に見せる場に参加できたことも、今回の経験になりました。

8．参加して得た学び
海外コミュニティへの参加

今回の参加を振り返ると、一番大きかったのは、新しい世界を見て、自分もそこに参加し始められたことだと思います。

ソフトウェアの世界には、国を越えたコミュニティがあり、カンファレンスがあり、それを支える役割や制度があります。名前を知っているソフトウェアの周囲に、こんなに多くの人の活動がある。その枠組みを、現地で少し実感できました。

仕事として海外のコミュニティに関わっている人や、それが当たり前の環境にいる人にとっては、自然な活動なのかもしれません。一方で、そうした接点が身近にない場合、参加するまでには心理的なハードルがあります。

目の前の仕事や勉強を頑張るだけでは、なかなか見つけられない入口もあります。今回は、応募し、公開の場で相談し、人に声をかけていただいたことが重なって、その入口に立つことができました。

今後のOSS活動

Apacheでは、コードや文書などに貢献する人を「コントリビューター」と呼びます。そこから、コードの変更を反映する権限を持つコミッターや、プロジェクト運営を担うPMCメンバー、財団の運営に関わるASFメンバーなど、さまざまな形で活動する人がいます。

今回会った人たちも、それぞれの形で開発やコミュニティを支えていました。自分も今後、継続して関わり、貢献を積み重ねていきたいと思います。その先で、コミッターやPMCメンバーなどの役割も担えるようになれたらと思っています。

OSSは、普段のソフトウェア開発を支える身近な存在です。その開発やコミュニティに自分も参加することで、見える世界や、つながれる相手が広がっていくと感じました。

先人の活動

ソニーでOSSの活動を進めてこられた方に、上田 理さんがいます。2023年に亡くなられましたが、公開されている資料を読む中で、その考え方に強く共感しました。

ソニーの公式記事では、世界中の人が企業や地域の壁を越えてOSSを育てることや、開発者コミュニティと信頼関係を築くことの大切さが語られています。OSSを利用する際のライセンス遵守を支援するプロジェクト、OpenChainの追悼記事にも、日本のOSSコミュニティや、企業を越えた協業、若い世代を支えた活動が紹介されています。

自分が今回感じた、技術を通じて世界の人とつながることの価値は、こうした先人の活動とも重なるものだと思いました。これから経験を積み、その思いを自分なりに引き継いでいける人になりたいです。

参加を考えている方へ

国内の勉強会やカンファレンスに参加するエンジニアは、身近にも増えているように感じます。一方で、海外のコミュニティに参加することには、まだ距離を感じる人もいると思います。自分もその一人でした。

だからこそ、この経験を共有することが、次に挑戦する人のきっかけになればうれしいです。日本から世界のコミュニティに参加し、開発や議論に加わる人が増えることは、日本の存在感を示すことにもつながると思います。

最初から大きな実績が必要だとは思いません。気になるプロジェクトを調べる、質問する、小さな改善に取り組む、発表に応募してみる。そうした一歩が、次の機会につながることがあります。

私の場合は、GSoCへの応募自体は不採択でした。それでも、そこで終わらずに、登壇と開発、そして現地での交流へとつながりました。

幼い頃からITに触れてきた人だけの世界でもありません。技術に興味がある人、世界の人と話してみたい人、コミュニティに関わってみたい人にも、入口があると思います。

国や会社を越えて一緒にものをつくり、顔の見える関係を増やすことが、世界の相互理解や、平和につながっていってほしい。少し大きな願いですが、私はそうした思いも持って、これから活動を続けていきたいです。

自分も、まだ参加し始めたばかりです。この体験が、誰かが世界のコミュニティへ一歩踏み出すきっかけになればうれしいです。
