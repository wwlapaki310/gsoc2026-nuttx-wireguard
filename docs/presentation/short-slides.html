何をやったか。WireGuard という VPN プロトコルを Apache NuttX に実装しました。 || WireGuard は Linux 向けに開発された軽量な VPN プロトコルで、組み込み・IoT 分野でも採用が広がっています。UDP 上で暗号化トンネルを確立し、使う暗号アルゴリズムは Curve25519・ChaCha20-Poly1305・BLAKE2s です。実装が約 4,000 行とコンパクトで、マイコン上での動作にも適しています。 || Apache NuttX は POSIX 準拠の RTOS で、独自の TCP/IP スタックと BSD ソケット API を持ちますが、現時点では VPN 機能がありません。今回は WireGuard を NuttX のネットワークデバイス、wg0 として実装しました。アプリケーションから見れば普通のネットワークインターフェースで、暗号化された中身を運んでいるのは UDP ポート 51820 のソケットです。通信相手は既存の WireGuard エンドポイントで構いません。

4 / 6
どう作ったか。ゼロから実装したわけではありません。wireguard-lwip という lwIP 向けの WireGuard 実装が先行事例としてあり、これを移植元にしました。BSD ライセンスで、NuttX の方針とも相性がいいです。 || この実装の良いところは、OS に依存する処理が4つの関数に隔離されていることです。単調増加時刻の取得、暗号乱数、TAI64N タイムスタンプ、負荷判定。プラットフォーム側が用意すべきものはこれだけです。 || したがってプロトコルと暗号のコア、約3,000行はそのまま持ってきて、lwIP の API を呼んでいる部分だけを NuttX の API に置き換える、という作業になりました。NuttX は lwIP ではなく独自のネットワークスタックを持つので、ここは流用ではなく書き直しです。wg0 は netdev_register で登録する仮想 NIC で、その配線は物理イーサネットではなく UDP ソケットになります。 || OS 固有の勘所については、同じコードを ESP32 の FreeRTOS 環境に移植した ciniml さんの WireGuard-ESP32-Arduino を先例として参照しました。 || この設計判断は当たりでした。結果として、4つのアーキテクチャでコードを1行も変えずに動いています。
