WireGuard という VPN プロトコルを、Apache NuttX という組み込み向けの RTOS に移植した話を、5分でご紹介します。 || ESP32-S3 の実機の上で、家庭用の Wi-Fi 越しに、Windows の公式 WireGuard クライアントと通信できるところまで確認できています。

What

アプリケーションから見れば、ただのネットワークインターフェース。

2 / 6
何をやったか。WireGuard という VPN プロトコルを Apache NuttX に移植しました。 || これまで NuttX の機器をデバッグするには、その機器のところまで行ってシリアルケーブルを挿すしかありませんでした。ログを見るのも、コマンドを叩くのも全部それです。NuttX には VPN の実装がなかったので、ほかに安全な遠隔手段がなかったためです。 || 今回の実装で wg0 という仮想的なネットワークインターフェースが生えます。アプリから見ればただの NIC なので、ssh でも telnet でも HTTP でも、普段使っている道具がそのままトンネルの向こうの機器に届きます。

3 / 6
なぜやったか。きっかけは GSoC のテーマ一覧でこの題目を見つけたことですが、やりたいと思った理由は仕事の方にあります。 || 私はソニーセミコンダクタソリューションズで、AITRIOS というエッジ AI プラットフォームに関わっています。そこで使っている AI カメラが ESP32 と NuttX の組み合わせです。それとは別に、ボトムアップの活動で SPRESENSE を使った人工衛星のプロジェクトにも関わっていました。 || この2つ、まったく違うものに見えて、困りごとが同じでした。現場に置いたあと、触れない。カメラは天井や屋外の高所に設置されることもあるので、異常の兆候だけで人を派遣するのは現実的ではありません。衛星に至っては、打ち上げ後の物理アクセスは不可能です。 || そのとき取りうる選択肢は多くありません。グローバル IP を晒してポートを開けるか、独自プロトコルを作り込むか、ベンダーのクラウドに寄せるか。どれも安全性か保守性か独立性のどれかを損ないます。本来は VPN で解決する話なのに、NuttX にはその選択肢がありませんでした。そして WireGuard は約 4,000 行と小さいので、マイコンに載ります。

How

4 関数だけ置き換える

移植元  smartalock/wireguard-lwip   github.com/smartalock/wireguard-lwip
Copyright (c) 2021 Daniel Hope (www.floorsense.nz) · BSD-3-Clause
lwIP 向けの WireGuard 実装。OS 依存が 4 関数に隔離されている
扱い規模
プロトコル・暗号無改変で流用約 3,000 行
OS 依存の 4 関数NuttX の POSIX API で実装186 行
lwIP netif グルーNuttX 用に書き直し約 2,700 行

結果: 4 アーキテクチャでコード変更ゼロ

x86_64 / ARM Cortex-A7 / Xtensa LX7 / ARM Cortex-M4F

4 / 6
どう作ったか。ゼロから実装したわけではありません。wireguard-lwip という lwIP 向けの WireGuard 実装が先行事例としてあり、これを移植元にしました。BSD ライセンスで、NuttX の方針とも相性がいいです。 || この実装の良いところは、OS に依存する処理が4つの関数に隔離されていることです。単調増加時刻の取得、暗号乱数、TAI64N タイムスタンプ、負荷判定。プラットフォーム側が用意すべきものはこれだけです。 || したがってプロトコルと暗号のコア、約3,000行はそのまま持ってきて、lwIP の API を呼んでいる部分だけを NuttX の API に置き換える、という作業になりました。NuttX は lwIP ではなく独自のネットワークスタックを持つので、ここは流用ではなく書き直しです。wg0 は netdev_register で登録する仮想 NIC で、その配線は物理イーサネットではなく UDP ソケットになります。 || OS 固有の勘所については、同じコードを ESP32 の FreeRTOS 環境に移植した ciniml さんの WireGuard-ESP32-Arduino を先例として参照しました。 || この設計判断は当たりでした。結果として、4つのアーキテクチャでコードを1行も変えずに動いています。
