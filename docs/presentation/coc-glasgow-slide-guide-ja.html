1. 全体像 — 5 分でわかるこのプロジェクト

1.1 一言でいうと

小さな組込み機器(NuttX が動くマイコン)を、普通の VPN(WireGuard)で、安全に遠隔操作できるようにした。

具体的には、NuttX という OS に wg0(ダブリュージー・ゼロ)という「仮想のネットワークの口」を追加した。アプリから見ると Wi-Fi の口(wlan0)と同じように使えるが、そこを通るデータは自動的に暗号化され、インターネットの向こうの PC まで安全に届く。

Apache NuttXアパッチ・ナットエックスマイコン向けの小さな OS(RTOS)。Linux のような書き方(POSIX)ができるのが特徴。Apache ソフトウェア財団のプロジェクト。

1.3 パケットの「入れ子」— VPN の正体

VPN は魔法ではなく、パケット(データの小包)を、暗号化した上で別の小包に入れて送るだけ。この入れ子をカプセル化かぷせるか(encapsulation、エンキャプスレーション)と呼ぶ。

プロジェクト概要

Project Overview
スライド 5 の画像を開く

アプリから見ると wg0 は普通の口。wg0 に送られたパケットは暗号化されて UDP で送られ、届いた UDP は復号されて「wg0 から来た」ことになる。

図の左側(NuttX RTOS の箱)を上から読む:アプリ → ネットワークスタック → 物理の口(eth0/wlan0)と仮想の口(wg0)が横並び → wg0 の下に UDP ソケット(ポート 51820)。wg0 は物理の口と同格に並んでいるのがポイント。

語読み方意味
netdevネットデブnetwork device。OS が管理する「ネットワークの口」1 つ分
eth0 / wlan0 / wg0イーサ・ゼロ / ダブリューラン・ゼロ / ダブリュージー・ゼロ有線 / 無線 / WireGuard の口の名前。末尾の数字は 1 つ目の意味
BSD socket APIビーエスディー・ソケット・エーピーアイプログラムが通信するときの標準的な呼び出し方。Linux と同じ書き方
UDP socket (port 51820)ユーディーピー・ソケット、ポート ゴーイチハチニーゼロWireGuard が暗号データを運ぶのに使う通信口。51820 は WireGuard の慣例の番号

語読み方意味

POSIXポジックスUnix 系 OS の共通ルール。open()・read()・pthread_create() などの書き方を定める
ANSIアンシC 言語の標準ライブラリ(printf など)の規格
VFSブイエフエスVirtual File System。いろいろな記憶装置を同じ「ファイル」として扱う仕組み

MCU / MPUエムシーユー / エムピーユーマイコン / もう少し大きいプロセッサ。※後で出る「MPU(メモリ保護装置)」とは別物

解決策:なぜ WireGuard か

Solution
スライド 11 の画像を開く

独自の仕組みやクラウドではなく、標準の VPN プロトコルで解決する。

理由噛み砕くと
Modern IP-layer VPNIP の層(パケット単位)で動く新しい VPN。設計が小さく単純で、IPsec(アイピーセック)や OpenVPN(オープンブイピーエヌ)よりコードがずっと少ない → マイコンにも載る
UDP transport, public-key peers運ぶのは UDP。相手は公開鍵で識別する。証明書の発行機関(CA、シーエー)も、毎回の複雑な交渉も要らない
Already everywhereLinux カーネルに標準で入っていて、Windows の公式クライアントもある。相手側に特別なソフトが要らない

落とし穴 1:成功の 0 が何もしていなかった

SO_RCVTIMEO
スライド 19 の画像を開く

「受信を待つのは最大○秒まで」と設定する呼び出しが「成功(0)」を返したのに、実際には効いていなかった。

WireGuard は「しばらく何も来なければ、こちらから handshake を始める」というタイマー処理を、受信待ちの合間に行う。受信待ちが永久に終わらないと、タイマーが回らない。

語読み方意味
setsockoptセット・ソック・オプトソケットに設定を与える関数
SO_RCVTIMEOエスオー・レシーブ・タイムオー「受信待ちのタイムアウト」という設定項目
recvfrom()レシーブ・フロムUDP でデータを受け取る関数。来るまで待つ
block / blocks foreverブロック処理がそこで止まって待つこと。forever = 永久に
chicken-and-eggチキン・アンド・エッグ鶏が先か卵が先か。互いが互いの前提になって進めない状態
deadlockデッドロック互いに待ち合って永久に止まること
教訓

関数が成功を返しても、設定が効いた証拠にはならない。しかも効いていない設定は、エラーではなく「止まる」という形で隠れる。

落とし穴 2:作れたのに、生き残らなかった

pthread_detach
スライド 20 の画像を開く

受信用のスレッドを作って「切り離した(detach)」が、wg コマンドが終わるとスレッドも止まっていた。ps にも出ない。

作った直後に usleep()(少し待つ)を入れるとスレッドの printf が出たので、作成自体は成功していた。

思い込み実際
pthread_detach()「親が終わっても生き続ける」「終わったときの後片付けを自動にする」だけ。寿命は変わらない
寿命を決めるもの—スレッドが属する task group(タスクグループ)。コマンドが終わると、そのグループのスレッドは全部終わる
語読み方意味
pthreadピースレッドPOSIX のスレッド(1 つのプログラムの中で並行して動く処理の流れ)
RX threadアールエックス・スレッド受信担当のスレッド
task groupタスク・グループNuttX で、1 つのプログラムとその中のスレッドをまとめた単位。Linux の「プロセス」に近い
psピーエス動いているタスクの一覧を出すコマンド

この問題は、後のカーネル版で「スレッドとソケットはドライバ(OS 側)が持つ」設計にすることで根本的に解消した(スライド 26)。

落とし穴 3:ping は通るのに TCP が死ぬ(いちばん良い話)

EBADF
スライド 21 の画像を開く

同じトンネルで ping は損失 0%、telnet の接続の最初の 3 回のやり取り(3-way handshake)まで成功するのに、その後に接続が死ぬ。

ログ:wg_encrypt_and_send: psock_sendto ret=-1 errno=9 EBADF — 「送信に使った番号(fd)が無効」というエラー。

なぜ ping で見抜けなかったか:ping の返事も TCP の最初の SYN-ACK(シン・アック)も、受信タスク自身が返していた。別のタスクから送る TCP のデータだけが失敗した。

修正:番号(fd)を経由しない内部 API psock_*()(ピーソック)で、ソケットの実体(struct socket)を直接使う。どのタスクからでも使える。

もう 2 つのバグ:同じ形

深いところでも、同じ型の失敗が出た。どちらも handshake の成功だけでは見えない。

(1) NuttX 自身の暗号のバグ — nonce の位置

ChaCha20-Poly1305 は、パケットごとに違う 12 バイトの値(nonce、ノンス)を使う。WireGuard ではそこにパケットの通し番号(counter)を入れる。NuttX は counter を前の 8 バイトに置いていたが、正しくは後ろの 8 バイト。

NuttX の中でこの関数を使う人が誰もいなかったので、ずっと見つからなかった。修正は 2 行で、ドライバとは別の crypto: PR として本家に出す。

(2) BUILD_KERNEL だけで起きるクラッシュ

wg_set_if() が相手の情報をスタック上の 6 KB の配列にコピーしていた。カーネルのスタックは 3 KB しかない。

31

設計判断:タイムスタンプ問題に無料の答えはない

A design call — TAI64N
スライド 31 の画像を開く

WireGuard の受け手(responder)は、受け入れた中で最大の handshake 時刻を覚え、それ以下の時刻は捨てる(古い handshake の録画を使い回す攻撃を防ぐため)。だから送り手(initiator)は、再起動をまたいでも自分の過去より新しい時刻を出さないといけない。

案書き込みRTC なしで救えるか判断
実時刻 + 起動中は後戻りさせない(high-water)なし救えない採用
毎回の時刻を保存するhandshake ごと救えるフラッシュが摩耗する。handshake の途中で書き込みが入る
範囲をまとめて予約して保存するN 回に 1 回救える「電源が切れても確実に書けた」という保証(耐久性の契約)が NuttX に無い
追いつくまで待つなし救えない待ち時間 = 前回の起動時間(30 日動いていたら 30 日)

締めの一文:「Linux と wireguard-go と同じ約束事を採用し、それが救えない場合(RTC なし)は、黙らずに警告を出すようにした。」 — これがスライドの made the case it misses say so。

落とし穴:再起動後に「ping が通るか」で確かめると、16 秒で成功してしまい何も証明しない。ping で相手側が handshake を始めるので、ボード自身の時刻が使われないため。だから実験では、ボードに何も送らずに「ボードから」つながるかを見た。

語読み方意味
responder / initiatorレスポンダー / イニシエーターhandshake を受ける側 / 始める側
RTCアールティーシーReal-Time Clock。電源を切っても時刻を保つ時計の部品
TAI64Nタイ・ロクヨン・エヌ秒(8 バイト)+ ナノ秒(4 バイト)の時刻形式。例:再起動前 400000006ab339ad1ad27480 → 後 400000006ab339c326be3680(後の方が大きい)
high-waterハイウォーターこれまでの最大値。起動中は時刻をこれより後ろに戻さない
durability contractデュラビリティ・コントラクト「書けたと返したら、電源が切れても残っている」という保証
wireguard-goワイヤーガード・ゴーGo 言語で書かれた WireGuard の実装

この問題は issue #14 として、判断のうえで未解決のままにしている(証拠が足りないからではない)。
