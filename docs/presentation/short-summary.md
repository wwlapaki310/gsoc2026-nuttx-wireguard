## 1. 何をやったか 〔55秒〕

**[要点]**
- WireGuard（VPN プロトコル）を Apache NuttX（組み込み RTOS）に移植した
- NuttX には VPN が **なかった**
- 従来: 現場の機器を触る = **シリアルケーブルを挿す**
- これから: **リモートから、暗号化された経路で**

**[話す]**
WireGuard という VPN プロトコルを、Apache NuttX という組み込み向けの RTOS に移植しました。

何が嬉しいかというと、これまで NuttX の機器をデバッグするには、その機器のところまで行って
シリアルケーブルを挿すしかなかったんです。ログを見るのも、コマンドを叩くのも、全部それ。
NuttX には VPN の実装がなかったので、ほかに安全な手段がありませんでした。

今回の実装で、`wg0` という仮想的なネットワークインターフェースが生えます。アプリから見れば
ただの NIC なので、`ssh` でも `telnet` でも HTTP でも、**普段使っている道具がそのまま**
トンネルの向こうの機器に届きます。リモートで、かつ安全に。

## 2. なぜやったか 〔95秒〕

**[要点]**
- きっかけは GSoC のテーマ一覧
- 仕事: ソニーセミコンダクタソリューションズ / エッジ AI プラットフォーム **AITRIOS**
  - そこで使う AI カメラが **ESP32 + NuttX**
- ボトムアップ活動: **SPRESENSE を使った人工衛星**
- **どちらも「現場に置いたあと触れない」**

**[話す]**
きっかけは GSoC のテーマ一覧でこの題目を見つけたことですが、やりたいと思った理由は仕事の方に
あります。

私はソニーセミコンダクタソリューションズで、AITRIOS というエッジ AI プラットフォームに
関わっています。そこで使っている AI カメラが ESP32 と NuttX の組み合わせなんです。
それとは別に、ボトムアップの活動で SPRESENSE を使った人工衛星のプロジェクトにも
関わっていました。

この2つ、まったく違うものに見えて、困りごとが同じでした。**現場に置いたあと、触れない。**

カメラは、いったん設置してしまえば手が届きません。天井や屋外の高いところに付いていることも
あるので、様子がおかしいというだけで人が見に行くのは現実的ではない。衛星に至っては、
打ち上げてしまえば物理的に不可能です。ネットワーク経由が唯一のメンテナンス手段になります。

そのときに何ができるかというと、選択肢は多くありません。グローバル IP を晒してポートを
開けるか、独自のプロトコルを作り込むか、ベンダーのクラウドに寄せるか。どれも嬉しくない。
**本来なら VPN を張ればいい話**なのに、NuttX にはその選択肢がありませんでした。

そして WireGuard は小さいので載る。だったらやろう、というのが動機です。

## 3. どう作ったか 〔60秒〕

**[要点]**
- 先行事例: **wireguard-lwip**（lwIP 向けの WireGuard 実装、BSD ライセンス）
- OS 依存が **4 関数** に隔離されている
- プロトコル・暗号（約 3,000 行）→ **無改変で流用**
- lwIP 依存部 → **NuttX の API に置き換えて書き直し**

**[話す]**
ゼロから書いたわけではありません。wireguard-lwip という、lwIP 向けの WireGuard 実装が
先行事例としてありました。BSD ライセンスで、NuttX の方針とも相性がいい。

この実装が良くできていて、**OS に依存する部分が 4 つの関数に隔離**されています。時刻の取得、
乱数、タイムスタンプ、負荷判定。それだけです。

なのでプロトコルと暗号のコア、約 3,000 行はそのまま持ってきて、**lwIP の API を呼んでいる
部分だけを NuttX の API に置き換える**、という作業になりました。NuttX は lwIP ではなく
独自のネットワークスタックを持っているので、ここは書き直しです。

結果として、この設計は当たりでした。**4 つのアーキテクチャで、コードを 1 行も変えずに
動いています。**

## 4. いまどこまで 〔55秒〕

**[要点]**
- **ESP32-S3 実機で動作確認済み** — 実 Wi-Fi 経由、相手は Windows 公式クライアント
- デモ動画: <https://youtu.be/1kyX2av5WG4>
- Raspberry Pi Pico 2 W — **挑戦中**（Wi-Fi チップのドライバが RP2350 側に無い）
- SPRESENSE — `wg0` の起動までは確認済み。**Wi-Fi モジュールを確保できたら**通信まで

**[話す]**
ESP32-S3 の実機で動いています。家の Wi-Fi 越しに、相手は Windows の公式 WireGuard
クライアント。**自作同士ではなく、本物の実装と通信できている**ところが大事だと思っています。

デモ動画があります。トンネル越しに telnet でログインして、ボードの上で Web サーバを起動して、
最後にブラウザで開きます。このとき USB は繋がっていません。電源アダプタだけです。

いまは Raspberry Pi Pico 2 W で挑戦中です。こちらは Wi-Fi チップのドライバが NuttX の
RP2350 側にまだ無いので、そこから。SPRESENSE は `wg0` の起動までは確認できていて、
Wi-Fi モジュールを確保できたら通信まで持っていきます。

## 想定質問（短時間枠でよく来るもの）

**Q. どのくらいの速度が出るの?**
ESP32-S3 の実機・実 Wi-Fi 経由で、トンネル越しの TCP が約 260 KiB/s です。

**Q. なぜ WireGuard なの? OpenVPN や IPsec は?**
実装の大きさです。OpenVPN や IPsec が十万行以上あるのに対して、WireGuard は約 4,000 行。
暗号スイートを固定してネゴシエーションをなくしたからで、**小さいということは組み込みに
載る**ということです。

**Q. 苦労したところは?**
「テストは通ったのに壊れている」というパターンを何度も踏みました。いちばん厄介だったのは、
`ping` は 0% ロスで通るのに TCP のデータだけが 1 バイトも届かない、というものです。
本編のスライドではそこを詳しく話しています。
